# 要件と施主の決定 — NeNe Swarm

> Status: normative（規範）/ 2026-10-27 初版
> 施主（hide）が言ったこと・決めたことだけを書く。**施主が言っていない大きな機能を要件に書かない・実装しない。**
> 細かい演出の判断は Q12 のとおり派手な方へ寄せてよい。施主から後で違う指示が来たら、それに従って変え、ADR で置き換える。

NeNe Swarm は、WSL2 の Ubuntu の端末（Windows Terminal）で、手作りの AI のパイロットが固定画面のシューティング（fixed shooter）を
自動で遊び続けるスクリーンセーバーである（Swift 製）。**TITLE → PLAY → GAME OVER → TITLE** を、`q` を押すまで繰り返す。

施主の依頼の要旨は「nene-gambit や nene-igo の規約やアプローチを踏襲して、昔のアーケードの固定画面シューティングのようなゲームを
プレイし続けるスクリーンセーバー。タイトル画面、プレイ、ゲームオーバーと繰り返す。カラーテーマと難易度がキー入力で変更出来て、
プレイヤーのボヤキやジョーク、喜びのセリフが出る」（元の言葉には実在のゲームの名前が入っているので、ここでは要旨にした。CNF-023）。

チェス版の [NeNe Gambit](https://github.com/hideyukiMORI/nene-gambit)・[NeNe Reversi](https://github.com/hideyukiMORI/nene-reversi)・
囲碁版の [NeNe Igo](https://github.com/hideyukiMORI/nene-igo)・[NeNe Poker](https://github.com/hideyukiMORI/nene-poker) と同じ形
（サイバー HUD・12 テーマ・4 名のキャストの減らず口・`install.sh` / `install.ps1` の 1 行で入る配布）を、シューティングで作る。
施主の方向づけは**派手でモリモリ**（Q12）で、兄弟より賑やかな画面にしてよい。
スクリーンセーバーに要るのは AI の強さではなく「見ていて飽きないプレイ」である。

🔴 **兄弟との一番大きな違いは、手番制ではなくリアルタイムであること。** ゲームは一定の刻み（tick）で進め、Core と Engine は時計を知らない。

## 1. 要件（FR）

| ID | 要件 |
| --- | --- |
| FR-01 | 端末に固定画面のシューティングを描く。自機は画面の下端を左右に動き、上へ弾を撃つ。敵は画面の上側に隊列を組む |
| FR-02 | **ゲームの形は 2 つの型を混ぜる**: (a) 隊列が左右に行進し、端に着くたびに 1 段下がる（行進は敵が減るほど速くなる）、(b) 隊列から一部の敵が抜け出し、曲線を描いて自機へ急降下し、撃ちながら画面の下を抜けて隊列へ戻る。敵は上から撃ち返す |
| FR-02a | **トーチカ**: 自機と隊列の間に 4 つの壊れる盾を置く。自機の弾でも敵の弾でも当たったセルが 1 つずつ欠け、下まで降りてきた隊列が触れたセルも消える。ステージが変わると元の形に戻る。形はこのリポジトリで新しく描く |
| FR-02b | **捕虜**: 2 発で倒れる特別な敵（親玉）が急降下して捕獲ビームを出す。ビームに入った自機は捕まり（1 機失った扱い）、隊列の中で親玉の隣に並ぶ。その親玉を急降下中に撃ち落とすと捕虜の自機が戻り、**2 機並び**（弾が 2 発ずつ・当たり判定も 2 機分・片方に当たったら片方だけ失う）になる。隊列にいる親玉を撃ち落とした場合と、捕虜の自機を撃ってしまった場合は、捕虜は戻らない。わざと捕まりに行くかはパイロットの性格で変える |
| FR-02c | **ボーナスの敵**: 画面の上端をときどき横切る UFO。倒すと大きな得点（得点は乱数で変わる）と派手な爆発 |
| FR-02d | **ボーナスステージ**: 3 ステージごとに、敵が撃ってこず編隊で飛び抜けるだけのステージを挟む。全部倒すと大きなボーナスと「PERFECT」の表示 |
| FR-02e | **ハイスコア**: 上位 5 件（得点・パイロット名・到達ステージ・難易度）を TITLE に出し、HUD に 1 位を出す。合成ルートだけがファイル（`$XDG_STATE_HOME/nene-swarm/`、無ければ `~/.local/state/nene-swarm/`）に読み書きし、読めない・書けないときは起動中だけの記録で続ける。新記録はパイロットが喜ぶ |
| FR-02f | **派手な演出**: 流れる星空の背景（ゲームの邪魔をしない暗い色）・敵ごとに飛び散る爆発・倒した場所に浮かぶ得点・親玉や UFO を倒したときの画面の一瞬の光り・ステージの始まりと終わりの大きな文字の帯（`STAGE 3`・`STAGE CLEAR`）・2 機並びになったときの演出。どれもテーマの色で描き、文字の読みやすさのテストを通す |
| FR-03 | **場面は 3 つで、閉じた enum で巡る**: TITLE（題・次のゲームのパイロット・難易度・キーのヘルプ）→ PLAY → GAME OVER（最終スコア・到達ステージ・パイロットの一言）→ TITLE。`q` を押すまで終わらない |
| FR-04 | **プレイヤーは AI のパイロット**。弾と急降下の敵を避け、敵を狙って撃つ。残機を持ち、被弾で 1 機失い、全部失ったら GAME OVER。パイロットは完璧ではなく、いつか必ず落ちる |
| FR-05 | **ステージ**: 敵を全滅させると次のステージ。ステージが進むほど敵は速く・弾は多く・急降下は頻繁になる（ゲームが必ず終わるため） |
| FR-06 | **毎回違うゲームになる**（シード付きの乱数で隊列の動き・急降下の選び方・敵の弾・パイロットの迷いを変える）。同じシード・キー入力なしなら同じゲームの列と同じセリフ |
| FR-07 | 自機・敵・弾・爆発は文字ではなく、**地とは別の色で塗った偶数桁のブロック**で描く。敵の形は**このリポジトリで新しく描いたもの**で、既存のアーケードゲームの絵を写さない |
| FR-08 | `q` で終了する。どんな終わり方でも端末を必ず元に戻す |
| FR-09 | 動作環境: WSL2 の Ubuntu＋Windows Terminal。入れ方は兄弟と同じ（`install.sh` と `install.ps1`） |
| FR-10 | 画面の横か上（HUD）に、スコア・ステージ・残機・難易度・今回のパイロット（名前と顔）・通算のゲーム数を出す |
| FR-11 | 刻みの速さ・TITLE と GAME OVER を見せる時間は起動オプションで変えられる。初期値は実機で見て決め、施主に知らせる |
| FR-12 | 12 テーマは兄弟の 12 種類（名前と配色の方針）を引き継ぎ、自機・敵（種類ごと）・自機の弾・敵の弾・爆発の色を足す |
| FR-13 | **カラーテーマは実行中のキー `t` で切り替え**、起動時は `--theme <名前>` で選ぶ |
| FR-14 | **難易度は EASY / NORMAL / HARD の 3 段階**。**実行中のキー `d` で巡り**、起動時は `--difficulty <名前>` で選ぶ。難易度が変えるのは敵の側（速さ・弾の数・急降下の頻度）だけで、パイロットの腕は変えない |
| FR-15 | **パイロットのセリフ**: ボヤキ・ジョーク・喜びのセリフを COMMS 欄に出す。英語で、ウィットに富んだブラック、ニヤッとしてしまうもの。**パイロットは 4 名（性格）で、ゲームごとに 1 名が乗る**。性格で撃ち方・避け方も変わる。セリフは 1 人 50 本 |
| FR-16 | キーのヘルプを画面のどこかに常に出す（`[q] QUIT  [t] THEME  [d] DIFFICULTY`） |
| FR-17 | 画面は兄弟の B 案（罫線の枠・端末の大きさで 2 段の配置・罫線が 2 桁で描かれる端末では自動で ASCII の枠に落とす）の構成に合わせる |
| FR-18 | **登録商標のゲーム名・会社名を、製品名・README・コード・セリフのどこにも書かない**（CNF-023 で機械が見る）。README では「固定画面のシューティング（fixed shooter）」と書く |

## 2. 施主の決定（2026-10-27）

| # | 論点 | 状態 |
| --- | --- | --- |
| Q1 | アプリ名 | **決定**: NeNe Swarm（`nene-swarm`）。元のゲームの名前は商標なので使わない（FR-18） |
| Q2 | 公開範囲とライセンス | **決定**（兄弟と同じ）: PUBLIC・MIT |
| Q3 | ゲームの形 | **決定**: 隊列の行進（a）と急降下（b）を混ぜる（FR-02） |
| Q4 | パイロット | **決定**: 4 名のキャストから毎ゲーム 1 名。性格で打ち方が変わる。セリフは 1 人 50 本・英語（FR-15） |
| Q5 | 難易度 | **決定**: EASY / NORMAL / HARD の 3 段階・キー `d`（FR-14） |
| Q6 | キャストの名前と性格 | **決定（推し）**: 実装側が決める。兄弟のキャスト（Gambit: VEX.EXE / MORT.SH / NULL_PTR / GRANNY.DLL、Reversi: FLIP.BAT / CORNER.SYS / SPAM.EML / LAZY.CRON、Igo: SENTE.SYS / TENUKI.LOG / MOYO.PNG / SEKI.LCK、Poker: BLUFF.EXE / NIT.BAK / ODDS.CSV / TILT.SH）と違う名前・違う性格にし、`ファイル名.拡張子` 風の名前と顔文字の作法はそろえる。性格ごとの寿命・スコアのばらつきは計測して ADR に書き、決めたら施主に知らせる |
| Q7 | 難易度を切り替えたときの効き方 | **決定（推し）**: 押した瞬間からプレイ中のゲームに効く。HUD の難易度の表示もすぐ替える |
| Q8 | 道具の導入 | **決定**（兄弟と同じ）: 開発用の道具は確認を待たずに入れてよい。製品の依存は ADR・許可リスト・規約の表の 3 点で管理する |
| Q9 | 進め方 | **決定**（兄弟と同じ）: フルゲートが緑なら、Ready・squash merge・Issue の起票は確認なしでよい。**Release の公開など外に出る操作は施主の確認を取る** |
| Q10 | トーチカ | **決定**: 入れる（FR-02a）。数・欠け方・ステージごとに戻すことまで施主の了承済み |
| Q11 | 捕虜 | **決定**: 入れる（FR-02b）。親玉が 2 発で倒れること・2 機並びの効き方・戻らない条件まで施主の了承済み。名前・見た目はこのリポジトリで新しく作り、元のゲームの呼び名を使わない |
| Q12 | 残りの判断の寄せ方 | **決定**: 施主「判断が必要なものは、派手でモリモリになる方にリナの判断で寄せて」。UFO・ボーナスステージ・ハイスコア・派手な演出（FR-02c〜f）はこれで入れた。寄せて決めたことは ADR に書き、区切りの報告で施主に知らせる。ただし規約とゲートを弱めない・文字の読みやすさのテストを通す・80 × 24 に入る・刻みの速さとちらつきの計測で決めた範囲を超えない・元のゲームの名前や絵を写さない |
| Q13 | 1 ゲームの長さ | **決定（推し）**: NORMAL で平均 3〜5 分を狙う。Phase 3 の計測で外れたら敵の強まり方を調整し、数字を ADR に書く |

**施主に聞いてから決めること**: 人間が操作して遊ぶモード・音（端末のベル）・既に決めた FR を削ること。

## 3. 不変条件（テストで守る）

シューティングには公表値が無いので、次の不変条件でゲートを組む（Phase 3）。

- **決定性**: 同じシード・同じ入力の列からは、同じ状態の列（状態のハッシュで比較）とセリフの列になる
- **範囲**: 自機・敵・弾は常に盤面の中（または画面外に出て消える状態）にある。弾は画面の外に出たら必ず消える。敵の数はステージの始まり以外で増えない
- **当たり判定**: 手で作った場面（ちょうど重なる・すれ違う・1 刻みで飛び越える速さ・同じ刻みに 2 発・自機と急降下の敵の衝突）で結果が一致する。**速い弾が 1 刻みで敵を飛び越えて当たらない罠を塞ぐ**
- **数の保存**: スコアは減らない・加点は敵の種類と状態の表どおり。残機は被弾でだけ 1 減る
- **トーチカ**: 欠けたセルは同じステージの中で戻らない・弾は欠けたセルを素通りする・ステージの始まりで元の形に戻る
- **捕虜**: ビームに入る / 外れる・急降下中の親玉を倒して戻る・隊列の親玉を倒して戻らない・捕虜を撃つ・2 機並びの片方だけ被弾・2 機並びのまま捕まる、で結果が一致する。自機の数（残機＋画面の自機＋捕虜）は表どおりに動く
- **場面の遷移**: TITLE → PLAY → GAME OVER → TITLE 以外の遷移は起きない
- **ゲームは必ず終わる**: 3 つの難易度 × 4 名のパイロット × 多数のシードで、全部が GAME OVER に着く。件数を黙って下げない
- **難易度の単調性**: 同じパイロット・同じシードの集合で、平均の寿命が EASY ≥ NORMAL ≥ HARD
- **パイロットの入力は常に合法**（画面の端より外へは動かない・撃てないときに撃たない）
- 端末サイズが変わっても落ちない。入らない小ささなら、必要な大きさを 1 行で出して待つ

## 4. やらないこと

- 施主に聞いてから決めること（人間が操作するモード・音・決めた FR の削除）を勝手に入れること
- 外部のゲームエンジン・物理や描画のライブラリを使うこと
- 既存のアーケードゲームの名前・会社名・敵の絵・効果音の名前を写すこと
- 不変条件のテストの件数を黙って下げること
