# ADR 0008 — パイロットは Core の 1 刻み関数で先を読んで避け、キャスト 4 名の性格で長さと遊び方を散らす

- 状態: 受理
- 日付: 2026-10-27
- Issue: #7
- 影響する規則: ARC-001 / ARC-004 / ARC-007 / FR-04 / FR-14 / Q4 / Q6 / Q13
- 置き換える範囲: ADR 0005 の「急降下は自機の方へ曲がりながら降りる」「ビームは盤面の下まで出す」の 2 点と、ADR 0007 の仮のパイロット `WanderingPilot`

## 文脈

Phase 3-2 までは、乱数で動くだけの仮のパイロットだった。施主の決定は、4 名のキャストから毎ゲーム 1 名が乗り、性格で撃ち方・避け方が変わること（Q4・Q6）、
パイロットは完璧ではなくいつか必ず落ちること（FR-04）、NORMAL の 1 ゲームを平均 3〜5 分にすること（Q13）。

最初の形（弾と急降下の敵を一直線に進むとみなして避ける）で 40 シードずつ測ると、NORMAL の平均は約 1 分だった。落ちた理由を数えると:

- **ビームを避けたい性格も 40 ゲームで 24〜36 回捕まった。** ビームは出た瞬間に盤面の下まで届くので、真下にいる自機は逃げようが無かった
- **体当たりが多かった。** 急降下の敵は下まで自機を追い続け、横の最高速度（4）が自機の速さ（4）と同じなので、横へ逃げても振り切れなかった。一直線の予測も外れた
- 慎重な性格（NERVOUS・SNIPER）は撃つのが遅く、隊列が降りきって終わる（invaded）ことが多かった
- EASY の方が NORMAL より短い性格があった（先読みが NORMAL の敵の速さを前提にしていた）

## 決定

### Core の調整（遊びとして公平にするため。ADR 0005 を置き換える）

- **捕獲ビームは親玉の下から 1 刻みに 4 単位ずつ伸びる**（`Game.beamGrowth`）。盤面の下に届くまで約 32 刻みあり、その間に横へ逃げられる。見た目も「伸びるビーム」になる
- **急降下の敵は、トーチカの 2 段上（`Game.commitAltitude`）より下では横の向きを変えない。横の最高速度は 3（自機より遅い）**。自機は横へ動けば突っ込みをかわせる

### パイロット（Engine の `Pilot`）

- 毎刻み、左・右・止まるを `foresight` 刻み先まで **Core の `Game.step` でそのまま進めてみて**、自機を失わない向きのうち、狙う位置に近づくものを選ぶ。
  どれも失うなら、失うのが最も遅い向きを選ぶ。第 2 の物理を書かない（ARC-001。指示書の「先読みに Core の 1 刻み関数を使うのは自由」）
- 先読みの乱数源は `Calm`（いつも最大の値を返す）。千分率の確率がどれも「起きない」側に倒れるので、先読みの中で新しい弾や急降下は始まらない。いま見えている危険だけを先へ進める
- 先読みには、いまの難易度を渡す。敵の速さを読むためだけで、パイロットの腕（性格の数）は難易度で変わらない（FR-14）
- 狙い: UFO を追う性格は UFO、2 機並びが欲しい性格は伸びているビーム、トーチカに隠れる性格は弾が来ているときに近いトーチカ、それ以外は弾が届くときの位置を先読みした一番狙いやすい敵
- 撃つ: 撃てるときに、弾が届くときにどれかの敵（か UFO）が真上の `aimTolerance` 以内にいれば撃つ。捕虜が弾の通り道にいたら撃たない
- 迷い: 千分率 `blindness` の刻みは危険を見ない。狙いは `±jitter` 単位ずれ、10〜30 刻みごとに選び直す。だから完璧ではない
- パイロットは Core の状態を読んで入力だけを返す（`PilotInput`）。入力はいつも合法（`canSteer`・`canFire` を見る）

### ゲートに入れる件数

`PilotTests` で **難易度 3 × パイロット 4 × シード 12 = 144 ゲーム**を最後まで回し、入力の合法性・刻みの上限に届かないこと・
平均の寿命が EASY ≥ NORMAL ≥ HARD であることを見る（release 構成で約 8 秒）。件数を黙って下げない。
Core の `InvariantTests`（テストのパイロット 2 名 × 600 ゲーム）はそのまま残す。ADR 0006 の表は、この ADR の Core の調整の前に測ったものである。

## 強制

- **active**: `PilotTests`（上）・`theCastHasFourNewMembers`（4 名・兄弟と重ならない名前・ASCII の顔）・`aCarefulPilotLeavesTheGrowingBeam`・
  Core の `theBeamGrowsDownFromTheFlagshipBeforeItReachesTheShipRow`・`aDiverBelowTheCommitLineNoLongerTurnsTowardTheShip`
- **active**（規約検査）: Engine は時計も乱数源も読まない（CNF-012。証明 P04 は `Pilot.swift` で取り直す）
- **planned**: 見ていて楽しいか（実機で見る・Phase 3-3 と 3-5）

## 結果

- 見ていて「避ける」「狙う」「わざと捕まって 2 機並びを取りに行く」が見える
- 1 刻みに最大 3 × 28 回 `Game.step` を回すので、パイロットの計算は Core の 1 刻みの数十倍になる。30 刻み／秒では十分速い（480 ゲーム・約 270 万刻みを release 構成で約 1 分）
- 失うもの: 先読みは「いま見えている危険」だけを見るので、次の刻みに撃たれる弾には反応が 1 刻み遅れる。それも「完璧ではない」の一部とした

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 弾と急降下の敵を一直線に進むとみなして避ける（最初の形） | 急降下の敵は曲がるので予測が外れ、Core の動きを Engine にもう 1 つ書くことになる（ARC-001） |
| 先読みでも本物の乱数源を使う | 先読みの中で起きない弾や急降下が見え、幻の危険から逃げる。本物の乱数源を進めると、ゲームの列も変わってしまう |
| ビームを出た瞬間に盤面の下まで届かせたまま、パイロットだけを賢くする | 真下にいる自機は物理的に逃げられない。避けたい性格でも捕まる回数が多すぎた（40 ゲームで 24〜36 回） |
| 急降下の敵を下まで追わせ続ける | 横の速さが自機と同じだと振り切れず、体当たりで落ちる割合が高すぎた |
| NORMAL の長さに合わせて `Tuning` を緩める | パイロットを直したら 3〜5 分に入った。敵の強まり方は変えていない |
| パイロットに難易度を知らせない | 先読みが NORMAL の敵を前提にすると、EASY の方が NORMAL より短い性格が出た（難易度の単調性が崩れる） |
| 性格ごとに腕前の数を難易度で変える | 施主の決定に反する（FR-14: 難易度が変えるのは敵の側だけ） |
