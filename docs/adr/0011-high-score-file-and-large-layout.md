# ADR 0011 — ハイスコアは版つきのテキストで XDG の状態の置き場に残し、100 × 26 以上では 2 段目の配置にする

- 状態: 受理
- 日付: 2026-10-27
- Issue: #13
- 影響する規則: ARC-004 / ARC-006 / ARC-008 / ARC-009 / FR-02e / FR-17

## 文脈

施主の決定（FR-02e）: ハイスコアの上位 5 件を TITLE と HUD に出し、合成ルートだけがファイル（`$XDG_STATE_HOME/nene-swarm/`、無ければ
`~/.local/state/nene-swarm/`）に読み書きする。読めない・書けないときは起動中だけの記録で続ける。
ARC-009: 永続化の形式は版を持ち、読めない版は既定値へ黙って落とさず型のある失敗で返す。`Codable` は CNF-015 で使えない。
FR-17: 画面は兄弟の B 案で、端末の大きさで 2 段の配置にする。Phase 3-2〜3-5b は 80 × 24 の配置だけだった（ADR 0007）。

## 決定

### ハイスコアのファイル

- 形式（版 1）: 1 行目 `nene-swarm-highscores 1`、2 行目から 1 件 1 行で `得点<TAB>ステージ<TAB>難易度（easy/normal/hard）<TAB>パイロット`。
  人が読めて、`Codable` も外部の依存も要らない
- 文字列と表の読み書きは Core の `HighScoreCodec` の 1 経路。版が違う・1 行目が無い → `.unknownVersion`、壊れた行 → `.malformedLine(行番号)`（閉じた enum）。
  読めた件数が 5 件より多ければ上位 5 件にする（並べ方は `HighScoreTable` の 1 経路）
- ファイルに触れるのは合成ルートの `ScoreStore` だけ（ARC-006）: 起動時に読み、ゲームが終わるたびに書く。書くときは一時ファイルに書いてから名前を替える。
  置き場のディレクトリは無ければ作る
- 読めないとき（読めない形式・開けない・置き場が決まらない）と書けなかったときは、起動中だけの記録で続け、TITLE に `SCORES KEPT IN MEMORY ONLY` と出す。
  ファイルがまだ無いのは失敗ではない（空の表で始めて、最初のゲームの後に作る）
- `XDG_STATE_HOME` は絶対パスのときだけ使う（XDG Base Directory の決まり）

### 2 段目の配置（FR-17）

- 100 × 26 以上: 盤面は同じ（52 桁 × 20 行）で、HUD を 45 桁に広げ、COMMS の代わりにハイスコアの上位 5 件を出す。盤面の下に COMMS の直近 2 行（古い方は控えめな色）
- 80 × 24〜: 今までどおり（COMMS は HUD の中に最新の 1 行）
- Windows Terminal の既定（120 × 30）は 2 段目の配置になる。`Banter` は直近 2 行を持つ

## 強制

- **active**（テスト）: 形式の往復・空の表・知らない版・壊れた行 7 種と行番号・5 件への切り詰め・2 段目の配置の中身と、99 桁では 1 段目に落ちること
- **active**（smoke）: 保存した表を読んで TITLE に出す・読めないファイルでは起動中だけの記録で続けて TITLE にそう出す。smoke の置き場はいつも一時ディレクトリ
- 書く経路は smoke では見ていない（1 ゲームが終わるまで 1 分ほどかかる）。2026-10-27 に疑似端末で HARD・60 刻み／秒で回し、54 秒で 1 ゲーム目が終わって
  `10650	5	hard	LUCKY.INI` が書かれたことを確かめた（**planned**: 書く経路を smoke に入れるかは、ゲートの時間とあわせて別に決める）

## 結果

- 再起動してもハイスコアが残る。壊れていても起動は止まらず、壊れていることが画面で分かる
- 大きな端末では、盤面の下でパイロットが続けてしゃべるのが読める

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| JSON で書く | `Codable` は使えず（CNF-015）、手で JSON を書くと読み書きの経路が大きくなる。5 件の表には行の形式で足りる |
| 読めないファイルを空の表として扱い、上書きする | 壊れた理由が分からないまま、前の記録を黙って消す（ARC-009） |
| ファイルの読み書きを Core に置く | Core はファイルを知らない（ARC-003）。読み書きは合成ルートだけ |
| 2 段目で盤面を大きくする（1 セル 3 桁） | Core の座標を桁に直す経路（`FieldMapping`）が 2 つになる。盤面は同じにし、HUD と COMMS に余白を使った |
| smoke で 1 ゲームが終わるまで待って書く経路を見る | 1 分以上かかり、証明のたびに `make check` が長くなる |
