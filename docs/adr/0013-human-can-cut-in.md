# ADR 0013 — 遊びのキーを押した刻みから人が操作し、触れなくなって 30 秒（刻みの数）で AI に戻す

- 状態: 受理
- 日付: 2026-11-28
- Issue: #24
- 影響する規則: ARC-004 / ARC-005 / ARC-006 / ARC-007 / SWF-013 / QLT-001 / FR-19 / Q15
- 置き換える範囲: ADR 0007 の `KeyIntent`（`q` `t` `d` だけを読む）を、この ADR の `KeyDecoder`・`HeldKeys`・合成ルートの `Controls` で置き換える

## 文脈

施主の決定（2026-11-28・Q15）: AI が遊び続けるだけだった Swarm に、「ゲームのキーを押すとその場から人の操作、30 秒触らなければ AI に戻る」を入れる。
形は兄弟の NeNe Bolt（Bolt の FR-04a・FR-04b・ADR 0007）に倣う。Bolt はこのリポジトリから作ったので、端末とループの作りがほぼ同じである。

縛りが 1 つある。hideyuki-mori-site の `swarm/`（TypeScript への移植）は、固定コミットの Swift の刻みのループと Render を、3 つのシード × 30,001 刻み × 2 つの大きさ
＝ 180,006 画面のハッシュで突き合わせている。**キー入力が無いときの動き・乱数の引き方・画面は 1 コマも変えない**。

## 決定

### キー（FR-19）

| キー | 意味 |
| --- | --- |
| `←` `→` | 動く（両方押していれば止まる） |
| Space・`z` | 撃つ（押しっぱなしなら撃てるたびに撃つ。撃てないときの引き金は Core が捨てる） |
| `q` `t` `d`・Ctrl+C | これまでと同じ（人の番でも効く。遊びのキーには数えない） |

上下は使わないので読まない。`x` も割り当てない（Bolt では「撃つ」だが、Swarm の撃つは 1 種類しかない）。

### キーの読み取り（Terminal・Bolt `072d08a` から移植）

- 起動時に Windows Terminal の win32-input-mode（`ESC [ ? 9001 h`）を頼み、端末を戻す列（`restoreTerminal`）の先頭で解く（`ESC [ ? 9001 l`）。異常終了のシグナルでも同じ列で戻す
- `KeyDecoder` が win32-input-mode の列（押した・離した）と、文字と矢印キーの列（文字として届いた）を同じ経路で読み、`KeyEvent` にする。`Key` は左・右・`z`・Space・`q`・`t`・`d`・Ctrl+C の閉じた集合
- `HeldKeys` が「いま押されているキー」を決める。押す・離すの方式では離すまで（くり返しが 1 秒途絶えたら離したとみなす）、簡易な方式では最初の 1 文字を 0.6 秒、くり返しが始まったら 0.12 秒。1 刻みの間の短い打鍵も次の 1 回は押していたことにする。どれも Bolt と同じ値
- これまでの `KeyIntent` は消した（`q` `t` `d` の意味は `Controls.Command` に移しただけで変えていない。大文字も同じに効く）

### 誰が操作するか（Engine の `Helm`）

- `Helm` は刻みの数だけを持つ純粋な値（Engine は時計を知らない）。合成ルートは毎刻み、入力を決める前に `advance(touched:)` を 1 回呼ぶ。
  `touched` は「この刻みに遊びのキーを押していたか」で、押しっぱなしを含む
- 触れた刻みから `handBack` 刻みの間は人、その次の刻みから AI。`handBack` は `--hand-back <秒>`（既定 30 秒・0.5〜60）を合成ルートが刻みの数に直したもの（既定の 30 刻み／秒で 900 刻み）
- Bolt は「最後に押した時刻（ミリ秒）」で決めていたが、ここでは刻みの数にした。理由: (1) Engine に置け、テストで刻み単位に確かめられる (2) ブラウザ版の突き合わせの台本に「何刻み目に押す・離す」を書け、Swift と TS が同じ `Helm` で同じ結果になる。
  描くのが遅れて刻みを捨てたとき（`maxCatchUp`）だけ、実時間の 30 秒より少し長くなる
- 人の番の PLAY の刻みでは、パイロットを呼ばず（パイロットの乱数を引かず）、人の入力をそのまま `Session.step` に渡す。人が何も押していなければ「何もしない入力」。
  AI に戻ったら、止まっていたパイロットがそのまま続きから飛ぶ
- セリフ・演出・Core の乱数は人の番でもこれまでどおり回す（COMMS のセリフは乗っていたパイロットが言い続ける）

### 表示（Render）

- `ScreenState` に `pilot: PilotLabel`（`.autopilot` か `.player(secondsLeft:)`）を足した。HUD の STATUS の PILOT の行だけが替わり、人の番なら `PILOT    YOU AI IN 27`（`YOU` は強調の色）
- AI に戻るまでの秒は合成ルートが残りの刻みから切り上げで出す（`LaunchOptions.seconds(ticks:)`）
- `.autopilot` のときは、これまでと同じセグメント（`PILOT` とパイロットの名前）を作る。キーのヘルプの帯（FR-16）・TITLE・GAME OVER の札は変えない。
  遊びのキーをヘルプの帯に足すと AI だけの画面が変わるので、キーは README と、ブラウザ版の説明の層に書く

### ハイスコア

- 1 ゲームの中で人が 1 度でも PLAY の刻みを操作したら、そのゲームの記録の名前は `PLAYER`（Bolt の FR-02g と同じ）。ファイルの形式は変えない

## 強制

- **active**: Engine のテスト `HelmTests`（触れた刻みから `handBack` 刻みだけ人・押しっぱなしで数え直す・誰も触れなければ `Helm` を通したループが通さないループと全刻みで同じ状態と同じ乱数の位置になる・
  人の入力が自機に効き、人の番の間はパイロットの乱数を引かず、AI が引き継いでゲームが終わる）
- **active**: Render のテスト（PILOT の行が AI ならパイロットの名前・人なら `YOU AI IN 07`・12 テーマで人の番の画面の英数字も 4.5:1 以上）と Terminal の `KeyTests`（Bolt から移植・上下と `x` を捨てる）
- **active**: `make check` の smoke 段（キーを押さなければ PILOT にパイロットの名前・win32-input-mode を頼む・矢印キーと win32-input-mode の列で `YOU AI IN` に替わる・
  `--hand-back 0.5` で `z` の後に AI に戻る・その列の `q` と Ctrl+C で終わり端末が戻る）と、証明 P49（端末を戻す列を壊すと smoke が落ちる。仕込む列を win32-input-mode を解く形に合わせた）
- **不能（この PR の中では）**: 「AI だけの画面がブラウザ版の正解と同じ」は、このリポジトリのゲートでは見ない（正解のデータは hideyuki-mori-site にある）。
  この PR では、hideyuki-mori-site の `swarm/golden/generator/main.swift` の刻みのループを `Helm` を通す形（触れない）に直し、`ScreenState` に `pilot: .autopilot` を渡して
  この枝の Core・Engine・Render で作り直し、`swarm/golden/data` と `diff -r` で全く同じ（180,006 画面のハッシュと 16 枚の画面の写し）であることを手で確かめた。ブラウザ版の移植の PR で台本ごと固定する
- **planned**: Windows Terminal の実機で win32-input-mode が WSL の中まで届き、押しっぱなしで動き・離すと止まること（Bolt の ADR 0007 と同じく、疑似端末はその代わりにならない・QLT-013）

## 結果

- 見ている人が、いつでも矢印キーで割り込んで遊べる。放っておけば 30 秒でスクリーンセーバーに戻る
- キーを押さない限り、これまでと同じゲームの列・同じセリフ・同じ画面（FR-06 のまま）。`--seed` の再現も変わらない
- 簡易な方式の端末では、離してから最大 0.12 秒（くり返しが始まる前は 0.6 秒）動き続ける。どちらの方式かは画面に出さない（出すと AI だけの画面が変わる）
- 人の入力は「パイロットの入力は常に合法」（REQUIREMENTS 第 3 節）の対象ではない。端の外へ動く・撃てないときに撃つ入力は、Core がこれまでどおり捨てる
- GAME OVER の札とセリフは、人が遊んだゲームでも乗っていたパイロットの名前で出る（変えると AI だけの画面の経路に分岐が増える。ハイスコアの表だけ `PLAYER`）
- ブラウザ版への移植で効く点: `Helm`（Engine・刻みの数）・`PilotLabel`（Render）・`ScreenState.pilot`・刻みのループの順（`advance` → 人か AI か → `Session.step`）。
  ブラウザは keydown / keyup が届くので `HeldKeys` の推し量りは要らない

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| Bolt と同じく、最後に押した時刻（ミリ秒）で人の番を決める | 判定が合成ルートの時計に縛られ、テストでもブラウザ版の突き合わせでも刻み単位に再現できない。刻みの数なら Engine に置ける |
| 人の番の間もパイロットを呼んで、入力だけ捨てる | パイロットの乱数がそのまま進むので AI に戻ったときの続きは自然になるが、人が触れない限りどちらでも同じで、呼ぶ分だけ遅い。呼ばない方が「人の番は人の入力だけ」が読みやすい |
| キーのヘルプの帯に `ARROWS MOVE  SPACE FIRE` を足す | AI だけの画面が変わり、ブラウザ版との突き合わせ（180,006 画面）が崩れる |
| HUD にキー入力の方式（押す・離すか、くり返しだけか）を出す（Bolt の FR-04b） | 同じ理由。人の番の間だけ出すこともできるが、施主の決定に無い表示を増やさない |
| 撃つキーに `x` も足す | 撃つのは 1 種類で、2 つで足りる（指示書の推し）。Bolt の `x`（撃つ）と `z`（跳ぶ）の区別は Swarm に無い |
