# ADR 0005 — 座標は 1 セル 16 単位の整数で持ち、ゲームは固定の順番の 1 刻み関数だけで進める

- 状態: 受理
- 日付: 2026-10-27
- Issue: #3
- 影響する規則: ARC-001 / ARC-004 / ARC-005 / ARC-007 / SWF-001 / SWF-002 / SWF-003 / SWF-014

## 文脈

兄弟は手番制で、Core は「合法な手を 1 つ適用する」関数だった。Swarm はリアルタイムで（REQUIREMENTS 冒頭）、毎秒何十回も状態を進める。
それでも Core は時計を知らず（ADR 0004）、同じシードからは同じゲームになる必要がある（FR-06）。

Phase 0 の実測（ADR 0001）から、座標の持ち方には次の制約がある。

- `Double.squareRoot()` は標準モジュールを import しない実行ファイルでリンクできない（X-i・X-j）。急降下の曲線を三角関数や平方根で描けない
- 負の数の `/` は 0 へ、`>>` は負の無限大へ丸める（X-k・X-l）。急降下の敵は負の速さを持つので、丸め方が混ざると左右で 1 セルずれる
- `Int32` の `+` は `-O` でも桁あふれで落ちる（X-m）

端末は 80 × 24 で、兄弟と同じく 1 セルを端末の 2 桁で描く（FR-07）。HUD と罫線の枠が要る。

## 決定

### 座標

- 盤面は **26 セル × 20 段**。1 セルは **16 単位**（`Field.cellShift = 4`）。座標は `Int`（64 ビット）で持ち、盤面は 416 × 320 単位なので桁あふれは起きない
- セルへの変換は `Field.cell(_:)` の 1 経路だけで、`>>` で**負の無限大へ丸める**（盤面の外の負の位置も一様に 1 つ外のセルになる）
- 速さは「1 刻みに何単位」で書く。Core に秒は現れない
- 曲線は**速さを 1 刻みに 1 単位ずつ変える**ことで描く（急降下は自機の方へ横の速さを ±1 ずつ寄せ、下向きの速さを 1 ずつ上げる。ボーナスステージの編隊は下向きの速さを 6 刻みに 1 ずつ減らして弧にする）。三角関数も平方根も使わない

### 1 刻み関数

- ゲームを進めるのは `Game.step(_:difficulty:using:)` の 1 経路だけ。状態＋パイロットの入力＋乱数源 → 次の状態と出来事（`GameStep`）。終わったゲームは変わらない
- `Game` の格納プロパティは `public internal(set) var`。他の target からは読むだけで、書けるのは Core の中だけ（SWF-003。CNF-016 は `public var` を拒み、`internal(set)` は通す）
- 戦っている刻みの順番は `Game+Advance.swift` の 1 か所で決める: 自機を動かす → 撃つ → 自機の弾 → 敵の動き（行進・急降下・戻り・ビーム・通り抜け）→ UFO → 敵が撃つ → 敵の弾 → 体当たり → 捕獲ビーム → 隊列とトーチカ → 隊列の到達 → 爆発の片付け → ステージの終わり
- 難易度は毎刻み引数で受け取り、`Tuning.make(difficulty:stage:)` で敵の強さに直す。押した瞬間から効く（Q7）
- 乱数は引数の乱数源からだけ引く（ARC-007）。`Set` と `Dictionary` の並びに依存しない（Swift の `Hasher` はプロセスごとに種が変わる）。状態はすべて配列とビットで持つ
- 場面（TITLE → PLAY → GAME OVER）は `Session.step` の 1 経路。TITLE と GAME OVER の長さは刻みの数で受け取り（`SceneDurations`）、秒への換算は合成ルートがする（FR-11）

### パイロットの入力

`PilotInput` は左右（`Steer`: left / right / hold）と引き金（`Trigger`: fire / hold）の組。指示書の「左・右・撃つ・待つ」を、動きながら撃てるように 2 つの閉じた enum の組にした。
Core は端より外への動きを止め、撃てないときの引き金を無視するが、パイロットの入力が合法か（`canSteer`・`canFire`）はテストで見る。

### 当たり判定

- 当たりの判定は `Box.overlaps` の 1 経路（辺が接するだけなら当たらない）
- **弾は 1 刻みの移動を 4 単位以下に刻み、刻むたびに当たりを見る**（`Game.path`）。4 単位はどの箱（弾 8・敵 16・自機 16・トーチカのセル 16）の高さより小さいので、どんな速さの弾も 1 刻みで飛び越えない
- 自機の弾は、トーチカ → 捕虜 → 敵 → UFO の順に見て、最初に当たったものだけに効く。敵の弾は、トーチカ → 自機の順
- 敵は動いた後の位置で、弾は敵が動く前に進める（順番が 1 つなので、同じシードで同じ結果になる）

### ゲームの中身（施主の決定 Q10〜Q12 を数にしたもの）

| 項目 | 値 |
| --- | --- |
| 隊列 | 6 列 × 4 段の席に 22 機（上の段の真ん中 4 席に親玉・次の段に護衛 6・下 2 段に雑魚 12）。席の間隔は 3 セル × 2 段。行進は半セルずつで、端で 1 セル下がる。1 歩の間は「難易度の刻み × 残りの機数 ÷ 22」（敵が減るほど速い） |
| 得点 | 雑魚 50 / 100・護衛 80 / 160・親玉 150 / 400（隊列の中 / 飛んでいる）。親玉は 1 発目では得点なし |
| 急降下 | 8 刻み上と外へ回ってから、自機の方へ曲がりながら降りる。下へ抜けたら画面の上から席へ戻る。降りながら撃つ |
| 捕獲 | 捕虜がいなく自機が 1 機のとき、親玉の急降下の半分が捕獲になる。9 段目で止まって 90 刻みビームを出す（幅 3 セル・盤面の下まで）。2 機並びはビームに入った方だけが捕まる |
| 捕虜の位置 | 親玉の 1 段上で、**半機ぶん右へずらす**。真上に重ねると親玉の陰になり、下からは決して撃てない（テストで見つけた・下） |
| 救出 | 隊列の外の親玉を倒すと、自機が 1 機なら 2 機並びに、並べないなら残機に戻る |
| 自機 | 2 セル幅・1 刻みに 4 単位・撃ったら 8 刻み待つ・1 機あたり画面に 2 発まで。始まりの残機は 2（画面の 1 機と合わせて 3 機） |
| トーチカ | 3 セル × 2 段のアーチ（5 セル）を 4 つ、14〜15 段目に左右対称に置く |
| UFO | 戦うステージで、消えてから 600 刻みごとに一番上の段を横切る。得点は 300 / 500 / 800 / 1000 / 1500 から乱数 |
| ボーナスステージ | 3 の倍数のステージ。5 機 × 4 波が左右から交互に入って弧を描いて抜ける。撃たない。1 機 100・全部で 10,000 |
| 終わり方 | 残機が尽きる・隊列が自機の段に届く・刻みの上限 36,000（30 刻み／秒で 20 分。安全のため。届いた割合は ADR 0006） |
| 強まり方 | `Tuning`。ステージ 1 つごとに行進の間が 1 刻み短く、急降下と隊列の弾の確率が千分率で 2 上がり、2〜3 ステージごとに同時の急降下・弾の数と速さが 1 上がる。どの値も難易度が上なら敵に有利か同じ |

## 強制

- **active**（テスト・ADR 0006）: 決定性・範囲・当たり判定（飛び越えを含む）・数の保存・トーチカ・捕虜・場面の遷移・必ず終わる・難易度の単調性・入力の合法性
- **active**（規約検査）: CNF-012（Core は時計・乱数源・環境を読まない）・CNF-011（Core は標準モジュールを import しない）・CNF-016（`public var` を書かない）・CNF-013（閉じた enum の全捕捉を書かない）
- **planned**（レビュー事項）: 刻みの順番を 2 か所に書かないこと

## 結果

- 刻みの速さを変えてもゲームの中身は変わらない。同じシードなら、30 刻み／秒でも 60 刻み／秒でも同じゲームになる（見える速さだけが変わる）
- 敵の箱は 2 セル幅なので、描くと 4 桁 × 1 行になる。敵の形（2 コマのアニメ・半ブロック）は Phase 3-2〜3-3 で Render が決める。Core の当たり判定は形によらない
- テストで見つけた設計の誤り: 捕虜を親玉の真上に重ねると、下からの弾はかならず先に親玉に当たり、「捕虜を撃ってしまう」（FR-02b）が起きえなかった。半機ずらした
- 失うもの: 当たり判定は箱だけで、敵の形のすき間は当たる。形に沿った当たり判定は要件に無い

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| `Double` で座標を持つ | libm にリンクできない（X-i・X-j）。丸めの違いで同じシードから別のゲームになる心配もある |
| 1 セル＝1 単位（整数のセルで持つ） | 1 刻みに 1 セル動く速さが最小になり、30 刻み／秒で自機が 1 秒に 15 セル（盤面の半分以上）動く。遅い動きが描けない |
| 座標を `Int32` で持つ | 盤面は小さく 64 ビットで足りる。`Int32` は桁あふれの検査が消えず（X-m）、得るものが無い |
| 経過時間（秒）を Core に渡す可変の刻み | 同じシードでも刻みの長さで結果が変わる（ADR 0004 の却下と同じ） |
| 弾を 1 刻みに 1 回だけ箱で当てる | 速い弾が敵を飛び越える（REQUIREMENTS 第 3 節の罠）。弾の移動を刻む |
| 移動の線分と箱の交差を計算で解く | 正しいが、トーチカのセル・捕虜・敵・UFO の順に「最初に当たったもの」を決める計算が箱の種類ごとに要る。刻む方が 1 経路で済み、テストで速さを変えて確かめられる |
| パイロットの入力を「左・右・撃つ・待つ」の 4 つの enum にする | 動きながら撃てず、どのパイロットも同じように鈍くなる。2 つの閉じた enum の組でも全捕捉なしで網羅できる |
| `Game` の格納プロパティを `let` にし、刻みごとに全部を作り直す | 20 個近い値を毎回すべて書き直すことになり、順番のどこで何を変えたかが読めなくなる。他の target から書けないことは `internal(set)` で守れる |
| 捕虜を親玉の横に並べる | 席の間隔は 3 セルで敵は 2 セル幅なので、横に並べると隣の席と重なる |
