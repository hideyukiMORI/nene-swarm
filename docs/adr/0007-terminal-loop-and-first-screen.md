# ADR 0007 — 端末と描画の土台を Igo から移し、30 刻み／秒の 1 本のループで 80 × 24 に描く

- 状態: 受理
- 日付: 2026-10-27
- Issue: #5
- 影響する規則: ARC-005 / ARC-006 / ARC-007 / ARC-011 / SWF-009 / SWF-013 / QLT-001 / QLT-013
- 置き換える範囲: ADR 0004 の「兄弟が後から広げた所（Igo の Terminal の `Synchronization`）は使うまで承認しない」を、この ADR で承認する

## 文脈

Core（ADR 0005）は画面なしで動き、不変条件のテストが緑になった（ADR 0006）。次は単純なパイロットのまま画面に出す（Phase 3-2）。
兄弟の NeNe Igo は、端末（termios・alternate screen・シグナル・差分出力・256 色への近似・罫線の幅の問い合わせ）と描画の土台
（格子・セル・枠・パネル・12 テーマ）を v0.1.0 まで通している。Swarm と違うのはリアルタイムであることだけで、Igo は 1 手 1 秒で描いていた。

## 決定

### 移植したもの（NeNe Igo `3bdae35`）

| このリポジトリ | 移植元 | 変えたこと |
| --- | --- | --- |
| `NeNeSwarmTerminal` の `Console`・`ConsoleOpening`・`ConsoleSignals`・`ConsoleState`・`CursorReport`・`FrameEncoder`・`Palette256`・`KeyIntent` | `Sources/NeNeIgoTerminal/` | 石の下線（SGR 4 / 24）を落とした。キー `d`（難易度）を足した |
| `NeNeSwarmRender` の `Cell`・`CellColors`・`ColorMode`・`Grid`・`Rgb`・`ScreenSize`・`Segment`・`FrameStyle`・`FrameGlyphs`・`Panel`・`TerminalTraits`・`DisplayOptions` | `Sources/NeNeIgoRender/` | 石の下線と棒グラフを落とした |
| `Theme` の 12 テーマの名前と 12 色 | `Sources/NeNeIgoRender/Theme.swift` | 色の値はそのまま。自機・敵・弾・トーチカの色は、仮に Igo の碁盤の地・線・印の色を当てた（下） |
| `NeNeSwarmEngine/SplitMix64` | `Sources/NeNeIgoEngine/SplitMix64.swift` | 変えていない |
| `nene-swarm` の `main`・`LaunchOptions`・`LaunchParsing`・`Screensaver` | `Sources/nene-igo/` | 1 手ごとの締め切りを、決まった間隔の刻みに替えた。`--version` は Phase 4 |
| `eng/smoke-terminal.py` | `eng/smoke-terminal.py`（#18 の直しを含む） | 端末を 80 × 24 にし、`d` と TITLE → PLAY を見る。差分で書くので、出力を小さな端末として再生した最後の画面で文言を見る形を足した |
| `Tests/NeNeSwarmTerminalTests` | `Tests/NeNeIgoTerminalTests` | 下線のテストを落とし、`d` と 256 色を足した |

`NeNeSwarmTerminal` の標準モジュールに `Synchronization` を足す（`Atomic` のシグナルの旗。Igo の ADR 0008 と同じ理由）。

### ループ（合成ルート `Screensaver`）

- 時計を読むのはここだけ。決まった間隔（`--tick-rate`、初期値 **30 刻み／秒**）ごとに `Session.step` を 1 回呼び、刻みのあとで 1 回描く
- 描くのが遅れたら最大 4 刻みまで追いつき、それ以上は捨てて今から数え直す（刻みの数は遅れに左右されるが、同じシードでキーを押さなければ同じゲームの列になることは変わらない。Core は刻みの数しか知らない）
- キーは刻みを待つ間に読む（`poll` の待ち時間を次の刻みまでにする）。`q` で終わり、`t` でテーマ、`d` で難易度を次へ。難易度は次の刻みから効く（Q7）
- 並行の形は 1 つ（SWF-013）: シグナルハンドラは原子的な旗を立てるだけで、異常終了のシグナルだけがその場で端末を戻す（Igo と同じ）
- パイロットは仮の `WanderingPilot`（乱数でしばらく同じ向きへ動き、撃てるときは撃つ）。ゲームが始まるたびに作り直す
- ハイスコアは起動中だけの表に入れる（ファイルへの保存は Phase 3-5・FR-02e）

### 画面（80 × 24 だけ）

- 上端に題の帯、左に罫線の枠で囲んだ盤面（26 セル × 20 段を端末の 52 桁 × 20 行）、右に 25 桁の HUD（STATUS と SWARM）、下端にキーの帯
- Core の座標を端末の桁と行に直すのは `FieldMapping` の 1 経路。1 桁は 8 単位（半セル）で、行は箱の真ん中の行
- 自機・敵・弾・トーチカ・爆発・ビームは空白のセルの背景色だけで描き、文字を書かない（FR-07・テストで見る）。敵は 4 桁で、2 コマで羽ばたく。弾は 2 桁
- 80 × 24 より小さい端末では 1 行の文言だけを出して待つ
- 大きな端末用の 2 段目の配置（FR-17）・専用の色・星空などの演出は Phase 3-5

### 計測（2026-10-27・疑似端末の 80 × 24・シード 1・30 刻み／秒・25 秒）

| 項目 | 値 |
| --- | --- |
| 1 秒あたりの出力 | 約 9.5 KB |
| 1 フレームのバイト数 | 中央値 238・95% 点 1,132・最大 6,484（最大は全面を書き直したフレーム） |

1 フレーム 1 回の `write` で、差分のセルだけを書く。Windows Terminal で詰まる量ではない見込みだが、ちらつきと見え方は
Phase 3-3 の実機の画面写真で確かめる（QLT-013。疑似端末は Windows Terminal の描き方の代わりにならない）。

## 強制

- **active**: `make check` の `smoke` 段（`q`・Ctrl+C・SIGTERM・SIGSEGV・大きさの変更で端末が戻ること・`t` と `d`・TITLE → PLAY・ASCII の枠への切り替え・起動オプションの拒否）と、証明 P49（端末を戻す列を壊すと smoke が落ちる）
- **active**: Render のテスト（80 × 24 に入る・キーのヘルプが常にある・盤面の色のセルに文字が無い・小さい端末・ASCII の枠）
- **planned**: 実機での見え方とちらつき（Phase 3-3 で画面写真）

## 結果

- 画面が出た。題・ハイスコアの表・ステージの帯・隊列・トーチカ・急降下・自機と弾が 80 × 24 に収まった
- 仮の色では、護衛（Igo の印の色）と自機（強調の色）がどちらも水色に近いテーマがある。Phase 3-5 で専用の色とコントラストのテストを入れて直す
- 失うもの: 大きな端末でも 80 × 24 の配置のまま（左上に寄る）。2 段目の配置は Phase 3-5

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 端末と描画を一から書く | Igo の土台は異常終了での復元・罫線の幅・256 色への近似・smoke の詰まりまで直してある。写さない理由が無い |
| 刻みと描画を別の速さにする（描画を 60 FPS など） | 刻みのあいだは画面が変わらないので、描いても書く差分が無い。1 本のループで刻みのあとに描けば足りる |
| 60 刻み／秒にする | Core の速さは「1 刻みに何単位」で決めてあり（ADR 0005）、刻みを倍にするとゲームが倍の速さになる。30 で見て、速さは実機で確かめる。起動オプションで 10〜60 に変えられる（FR-11） |
| 遅れたぶんの刻みを全部追いつく | 端末が詰まると刻みが溜まり、追いつく間に画面が飛ぶ。4 刻みで打ち切る |
| `d` で難易度を変えたら画面を全部書き直す | 差分だけで足りる。smoke は出力を再生した画面で文言を見る |
| Phase 3-2 で 12 テーマの専用の色を決める | 色はコントラストのテストとセットで決める（FR-12・指示書 第 2-3 節 6）。画面の形が実機で決まってから（Phase 3-3）の方が手戻りが少ない |
